# 新建工程导入全链路 · 坑与修复（2026-11-01 晚）

目标：新建工程 → 导入 6.5 万条音效 → 导入知识包 → 直接可用。
最终实测：音频 64554 / 文本 64554 / 失败 0（剩下 597 条是包里没有的文件）。

## 七个坑，按踩到的顺序

| # | 现象 | 根因 | 修复 |
|---|---|---|---|
| 1 | 导入卡在「正在扫描文件 9%」 | preparing 阶段每文件写一次库、主循环又写一次；每条 fsync；4 线程抢 SQLite 写锁 | preparing 不写库；DB 写走单线程 executor |
| 2 | 取消导入后，下一次导入卡在 0% | 批量提交的 begin/end 跨 await，取消时事务悬挂 | 回退批量提交，改逐条 commit |
| 3 | 进度突然停住，日志 `Set changed size during iteration` | `broadcast` 遍历连接 set，await 期间被并发 discard | 遍历 `list()` 副本 |
| 4 | 报错 `KeyError 'client_xxx'` | 同一个函数清理时直接索引 `active_connections[client_id]` | 改用 `.get()` |
| 5 | 知识包写描述卡在 64554 | 6.5 万条 FTS 同步 + 描述写入，磁盘被打满，界面请求超时 | 知识包导入跳过 FTS，后台慢速补；每批让锁 30ms |
| 6 | 补时长和知识包互相卡死 | 两条链路同时写 files 表 | 新增 `core/heavy_task.py` 闸门，同一时刻只许一个重活 |
| 7 | 文本向量已索引 0、待索引 65151 | 本机 `text_vector` manifest 的 `dimensions` 是 None，`validate()` 判定「维度不匹配」整包拒收 | 本机缺这项就跳过该项校验（其它项仍校验） |

## 关键认知

- **SQLite 只有一个写者**。导入、补时长、哈希补算、知识包、波形五条链路都在写 `files`，
  不排队就必然互相等 `busy_timeout`，表现就是「进度不动 + 界面读取失败」。
- **进度推送不该在关键路径上**。WS 一抖，导入就跟着死（坑 3、4 都是这个）。
  现在的做法是 WS 只当加速，轮询兜底一直开着。
- **失败要留证据**。坑 7 查了半天，就因为向量导入失败时没有日志。
  现在每个 kind 都有「开始 / 完成 / 失败原因 / 异常堆栈」。


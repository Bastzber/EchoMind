## 七、这轮没修掉的：启动期还有 8~9 次 3 秒卡顿

```
现象  冷启动过程中，「[Loop] 事件循环卡顿 3.0~3.3s」出现 8~9 次，合计约 25 秒
栈    全部指向 core/indexer.py:198 collection_engine_fingerprints
      另外两条是 indexer.py:983 _refresh_engine_state 调用它
原因  搜索热路径上次改成了「缓存 + 丢线程」，但启动阶段 searcher/indexer 构造时
      走的是不带缓存的那次扫描，六万五千行 metadata 要分 65 批读，一次约 3 秒
影响  只影响启动（窗口出来之前），不影响用起来之后的交互；
      但它实打实让冷启动慢了半分钟
```

下一步（两条路，下次开工再挑）：

```
A 把「整表扫描」换成「读 Chroma 自己的元数据表做 distinct」——一次 SQL 就能拿到指纹集合，
  但用的是 chroma 内部表名，升级 chroma 时要跟着改
B 启动时先起一个线程把指纹扫一遍预热缓存，searcher 构造改成等这个缓存（cached=True），
  代价是构造要等线程，但主线程不被占住
```

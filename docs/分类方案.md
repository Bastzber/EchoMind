# 音效库分类方案（v3 · 采用大羽体系）

> v2 的结论仍然成立（目录=浏览、标签=精选、搜索=主力），但**分类标准**直接采用
> 「大羽音效库」的 14 个一级分类 —— 它按材质/用途切分，覆盖面完整，而且
> 大羽包本身（34,130 个文件）就是这个结构，整合时零转换。

## 一、统一目录结构

```
D:\音效库\
  <一级分类>\<二级分类>\<文件>
```

最多 3~4 层（大羽原库有 5~6 层，整合时把"形态层"（连续/单次/循环）并进文件名或标签）。

## 四、整合步骤

1. **建新库根** `D:\音效库\`，按 14 个一级分类建目录
2. **大羽包直接搬**：`F:\大羽音效库集合包V1.0\*` → `D:\音效库\*`（结构一致，34,130 个文件）
3. **老库按映射表搬**：先搬 80% 明确的，剩下 3 个混合目录逐个过
4. **重新导入**：EchoMind 指向 `D:\音效库`
5. **标签只保留精选**（类型/场景/特性共 20~37 个）

## 五、风险与工具需求

| 风险 | 缓解 |
|---|---|
| 剪辑工程引用旧路径会断 | 记录映射表；提供回滚清单；或先只做软件内逻辑映射，不动磁盘 |

| 搬错 | 先 dry-run 出 CSV，确认后再执行 |

- `scripts/migrate_library.py`：读映射表 → 预览（dry-run 出 CSV）→ 执行移动 → 写回滚清单

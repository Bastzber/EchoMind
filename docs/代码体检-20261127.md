## 第二轮的结论：批量清 import 不能这么干

试过 AST 分析和纯文本分析两版脚本，各删掉 ~300 行未使用 import，两次都在运行期翻车：

- `core/db_files.py` 里的 `Path(...)` 不是自己 import 的，而是从 `from core.db_common import *` 漏出来的
- `db_common.py` 里那些看似「没用」的 `Path / datetime / time / threading / shutil`，实际是给 5 个 db_* mixin 用的公共符号

也就是说：**这个仓库里 import 不是模块私有的，是星号导入共享的**。任何单文件级别的「未使用」判断都不成立。已全部回退，后端回到提交状态并重新打包验证。

正确顺序应该是：
1. 先把 `core/db_*.py` 的 `from core.db_common import *` 换成显式名单（一次性，5 个文件）
2. 再跑批量清理，配套跑一遍索引/搜索/转码回归
3. 单独一个分支做，不和 UI 改动混在一起

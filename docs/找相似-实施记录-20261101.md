# 「找相似」实施记录（2026-11-01 凌晨）

## 一、需求与口径（用户确认）

主列表右键菜单加「找相似」，排在「添加/编辑标签」之前。
针对「猪叫」这类一族多形态的音效（成年猪 / 幼年猪 / 野猪音色都不同，但都属于猪叫）：

- **标签 + 描述 + 音频向量混合打分**
- **标签/描述命中的排在前面**，音频向量（听感）命中的接在后面
- 不把自定义文件夹 / 系统分类算作同类依据（范围会失控）
- 结果上限 100 条

### 同类段为什么不用文本向量

最早是「标签+描述拼成一句话 → CLAP 文本塔 embedding → 查文本索引」，三个坑（都有实测）：

1. 父进程的 CLAP 在音频索引时被 release_gpu() 释放，重新加载要 **15~25 秒**；
2. 模型没就绪时异常发生在后台线程里，join 超时后**静默返回空**，界面显示「同类 0 条」还没有提示；
3. 更关键：CLAP 文本塔对中文标签近似「词袋」，实测「猪 001」的邻居是猫/羊/牛——因为共享「低频/短尾/叫声」。

改成**词命中 + IDF 倒排**：中文按单字、英文按词，按 DF 加权。
「低频/高频/短尾/连续」这类几乎每个文件都有的听感标签会被 IDF 压到接近 0，并被
`_POSTING_CAP` / `_COMMON_TOKEN_RATIO` 剪掉；「猪」「家养动物」「BOAR」这类稀有词才是主信号。
排序用**相对阈值**（与本次最高分比，低于 25% 丢弃），避免大小库之间阈值失衡。

### 听感段

直接读这条文件**已入库的 CLAP 音频向量**去查余弦邻居（不再重新编码），阈值 0.55。
向量没就绪时横幅会注明「该文件音频向量未就绪，只按标签/描述」。

## 四、已知取舍

- 倒排缓存 10 分钟：新导入的文件最多 10 分钟后才进入「同类」候选（音频段不受影响）
- 中文按单字匹配，「猪」能命中「小猪/一头猪/豪猪」，代价是极少数单字噪音（已用 IDF + 相对阈值压制）
- 同类段用的是缓存快照，编辑标签后不会立刻反映（下次重建/超时后生效）

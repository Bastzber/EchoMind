### 六、第二轮重构（10-31 下午）

#### 做法

`index.html` 的内联脚本是一个整体（第 1034 行开始），但大部分内容在**顶层作用域**：
顶层 `function` 声明会成为全局函数，顶层 `const/let` 进入全局词法环境，跨 `<script>` 共享。
所以把整段顶层代码搬到独立文件、在原位置留一个 `<script src>`，语义完全不变。

#### 关键教训：按注释切分会把函数拦腰截断

第一次搬「右键菜单」时直接用 `// ===== 区块 =====` 当边界，结果文件语法检查失败——
区块末尾几行其实属于下一个函数。改成**按大括号平衡回退**找到真正的结束行后才通过：

```python
end = next_section_start
while end > start and balance(start, end) != 0:
    end -= 1
```

#### 又踩了一个坑

「源目录板块」直接按区块切分时语法检查失败：区块最后一行
`reportUiError('未处理的异常', event.reason);` 属于另一个全局错误处理器。

改成**只搬括号自平衡的完整顶层函数**（不是整段区块），通过。

随后「WEB SOCKET」区块又因为逐个函数扫描导致 O(n²) 卡到超时，
改成**前缀深度数组**预先算好每行的括号净变化，找函数结尾变成 O(1)。

```python
prefix = [0]
for d in delta: prefix.append(prefix[-1] + d)
# 函数结尾 = 第一个 prefix[j+1] 等于起始 prefix[i] 的 j
```

#### 为什么收效不大

剩下的「独立浮动面板」「初始化语言设置」等区块**不是函数**，是立即执行的初始化代码：


风险大于收益，所以不动。

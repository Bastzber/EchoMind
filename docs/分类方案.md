# 音效库分类方案（v4 · 对标大羽软件）

> 前三版都在讨论"目录怎么切"。看了大羽软件的真实数据结构（library.sqlite）才发现：
> **它的分类根本不靠目录，而是"目录镜像磁盘 + 每条音效 6 个标签 + 一句 AI 描述"。**

## 一、大羽软件的数据模型（实测）

| 表 | 行数 | 作用 |
|---|---|---|
| roots | 3 | 库根目录（可挂多个来源） |
| folders | 1,099 | **镜像磁盘目录**，带 displayName（可在软件里改名而不动磁盘） |
| assets | 34,190 | 每个音效一条：path/folder/description/tags/favorite/rating/usageCount |
| class_folders | 5 | 虚拟分类（只用于"我创作的声音"：AI 音乐/音效/人声/创造） |
| search_* | 34,190 | FTS 全文索引 |

关键点：**folders 只是磁盘结构的镜像**（含 displayName 覆盖），分类信息全在 assets.tags。

## 二、大羽的标签体系（重点）

```
资产总数        34,190
有标签           34,187（100%）
有 AI 描述       34,187（100%）
每个音效标签数     平均 6.0（33,346 条正好 6 个）
不同标签总数      4,004
```

| 频次 | 标签个数 | 含义 |

| >=1000 次 | **38** | 受控词表（形态/频段/质感/强度） |

| 10~99 | 832 | 具体名词 |
| <10 | 2,913 | 长尾自由词（空灵、梦幻…） |

## 三、结论：标签 = 6 个可筛选维度

| 维度 | 取值（受控） | 作用 |
|---|---|---|
| 形态 | 连续 / 单次 / 循环 / 长尾 / 短尾 / 掠过 / 上升 / 下沉 | 能不能当循环用 |
| 频段 | 低频 / 中频 / 高频 | 混音时筛 |
| 质感 | 电子 / 金属 / 木质 / 玻璃 / 空气 / 失真 | 配器时筛 |
| 强度 | 强烈 / 中等 / 柔和 / 轻微 | 情绪强度 |
| 空间 | 干声 / 混响 / 远场 / 近场 | 混音空间 |
| 语言 | 中文 / 英语 / 男声 / 女声 / 对白 | 人声专用 |

剩下 2~3 个用**自由词**（钢琴、空灵、梦幻、悬疑），由 AI 依据描述生成，人工可改。

所以 4,000 个标签也不乱：高频 38 个是受控的，长尾只是补充描述，
而且每条只有 6 个 —— 不是把目录名灌进去。

## 四、对 EchoMind 的改造建议

| 能力 | 现状 | 要做的 |
|---|---|---|
| 目录 | 有（跟随磁盘） | 加 displayName（软件内改名不动磁盘）+ 跟随磁盘同步 |
| 标签 | 有（手动） | 分"受控 38 词 + 自由词"，受控词做成按钮 |
| 描述 | 有 AI 一句话 | 复用：语义搜索 + 自动生成自由标签 |
| 自动打标 | 无 | **AI 自动打 6 个标签**（受控词表 + 自由词），治本 |

## 五、整合大羽库的落地步骤

1. 大羽包 34,130 个文件直接搬进 `D:\音效库\`（它已经是 14 类结构）
2. 搬家后，**把大羽的 tags/description 一起导出、导入 EchoMind** —— 它 34,187 条描述 + 6 个标签可直接复用
3. 老库（CJ/秋拾）按映射表归入 14 类
4. 老库的音效用 AI 批量生成描述 + 标签（补上大羽已有的那部分）

> 第 2 步价值最大：大羽已经给 34,190 条音效打好了 6 个标签和一句话描述，
> 迁移时白捡一套标注数据，不用重新跑 AI。

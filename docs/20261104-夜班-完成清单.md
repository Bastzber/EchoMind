## 二、事件循环卡顿：找到真凶了

### 先修探针（不然永远查不出）

老的卡顿探针自己跑在事件循环里，卡住之后才醒来取栈，取到的永远是探针自己那一帧。
翻日志看到的 125 条记录，栈全是 `main.py` 的 `_loop_lag_watchdog`，等于白记。

改成：事件循环只推心跳，另起守护线程盯心跳；心跳三秒没动，由那个线程 dump 主线程当前栈。

### 真凶：搜索引擎每次都要把整个向量库扫一遍

```
search_engine.search_async → searcher.is_compatible_with
  → collection_engine_fingerprints → collection.get(1000 行 × 65 批)
```

一次搜索里这个检查被问三遍，每遍三秒，全在事件循环上跑 —— 界面就那么卡住了。

### 怎么改的

```
1 指纹扫描按（集合名 + 行数）缓存 20 秒
2 写入时（bump_collection_revision 里）就地作废缓存
3 首次未命中缓存的那次扫描丢进线程池，不占事件循环
4 /api/v1/projects/{id}/index/status 里两处同步全表统计也丢线程池（那条单独卡 3.5 秒）
```

### 实测对比（同样的三个搜索词）

```
          改之前                 改之后
卡顿条数   9 条（每条 3.0~3.3 秒）  1 条（3.5 秒，来自 index/status，已单独修）
关键词阶段 6.45 秒                0.15 秒
音频阶段   4.77 秒                0.37 秒
```

## 三、日志改成攒批写

```
老写法   一条日志一次 stream.write，索引跑起来一秒几十上百条同步小写入
新写法   先进内存队列，攒够 64 KB 或过 400 毫秒再一次性落盘；退出前强制冲一次
```

## 四、Electron 45：查清了，而且转正了

### 之前为什么一放声音整个程序就没

三件事叠在一起，缺一条都复现不出来：

```
1  自定义协议缺少 stream: true      → 音频被判「不支持的源」(err=4)
2  响应没带 Content-Length          → duration 算成 Infinity，点波形跳转抛 non-finite
3  换上带令牌闸门的新后端之后        → IPC 代理和启动阶段那几个请求不带令牌，一片 401
```

排查过程中逐条排除的（都做了对照实验）：Electron 本身无辜、前端脚本无辜、沙箱无关、显卡无关、
后端进程无关。真凶全在协议响应和请求头这两处细节上。

## 七、今晚踩到 / 记住的坑

```
- 本机环境里有 ELECTRON_RUN_AS_NODE=1（DSH 注入），直接 Start-Process 会把 exe 当 node 跑，
  报 bad option: --remote-debugging-port。脚本里先 Remove-Item Env:ELECTRON_RUN_AS_NODE。
- 单实例锁：上一个实例没退干净时，新起的会立刻自己退，看起来像「一闪就没」。测之前先 taskkill。
- 改后端源码之后必须重打 exe 才会生效；要看改动效果可以临时用 SOUNDBOT_BACKEND_DEV=1 跑源码后端
  （但打包版走的是 exe，这条只在源码树里有效）。
- 老后端没有令牌闸门，会掩盖掉前端漏带令牌的问题；换新后端时一次性全暴露。
```

# PR 面板：自然语言搜音效（2026-11-01）

目标：在 Premiere Pro 里用一句话搜本地音效库，试听、看波形，一键导入项目。覆盖 PR 2022 ~ 2025。

## 一、形态与取舍

| 选择 | 为什么 |
|---|---|
| **CEP 扩展**（不是 UXP） | PR 的 UXP 面板 2023 才有，覆盖不到 2022；CEP 从 2022 到 2025 都能加载。代价是 Adobe 在淘汰 CEP，退路是同一套 HTML/JS 换成 UXP 只需改 manifest + 导入调用 |
| 自然语言解析放后端 | 面板是明文 JS，DeepSeek Key 必须留在本机后端；解析要复用现有 LLM 配置 |
| 词命中优先 + 语义可选 | 实测纯向量对中文短句不敏感（「低沉的猪哼」返回鼓点），词命中能精准命中「猪」「哼」；语义单次 6~15 秒，默认关闭 |
| 导入到项目面板，不做拖时间线 | PR 面板 API 不支持把素材直接塞进时间线，QE DOM 跨版本必炸 |

## 二、新增的东西

| 文件 | 作用 |

## 四、安装与使用

1. 完全退出 PR → 双击 `premiere-panel/安装到PR.bat`（拷到 `%APPDATA%\Adobe\CEP\extensions\com.echomind.panel` + 写 `PlayerDebugMode=1`）
2. 重开 PR → 窗口 → 扩展 → EchoMind 音效搜索
3. EchoMind 要在后台跑；想用 AI 解析就在设置里配 DeepSeek（不配会降级成关键词搜索，面板有提示）

## 四之二、试听为什么一开始失败（11-01 14:4x 修）

PR 里点「试听」报「播放失败」——不是面板的问题，是**文件编码**：
`打雷（雷后余声）.wav` 头里 `format_tag=17`（IMA ADPCM），Chromium 解不了这种 WAV，
`<audio>` 直接给 `MEDIA_ERR_SRC_NOT_SUPPORTED(4)`。

修法：后端 `GET /api/v1/files/{id}/audio?transcode=1` 用 PyAV 转成 PCM16 WAV 再吐，
按 `(uuid, mtime, size)` 缓存。面板的播放链改成：

```
CEP 里 Node 直读 → 原文件直连 → 转码后直连 → 转码结果抓 Blob
```

实测：`打雷（雷后余声）.wav` 转码 2.01 秒（首次）/ 0.02 秒（命中缓存），
转完 `readyState=4`、时长 10.26s、正常播放；PCM WAV 不受影响，仍走直连。

## 四之三、两种搜索模式（11-01 15:2x）

用户要「两个都要」：面板加开关，**默认精确**，需要时切语义。

| 模式 | 引擎 | 典型耗时 | 结果 |
|---|---|---|---|
| 精确（默认） | IDF 倒排 + 整词/bigram 覆盖度 | 冷启 5~20 秒（建倒排 + LLM），热 1 秒 | 字面命中，如「转场 whoosh」直接给出 whoosh 文件 |
| 语义 | 和软件里同一条混合搜索（CLAP 向量 + 文本 + 关键词） | 首次 10~30 秒，命中查询缓存后 0 秒 | 和软件界面完全一致 |

关键修正：

1. **词命中从单字改成 bigram**。原来「嘟 转场」里单字「场」会命中 4000 多个含「现场」的文件，
   导致手术液体声排在转场音效前面；改成 bigram（转场/婴儿/笑声）后既准又能部分匹配
   （「婴儿笑声」能匹配到「婴儿笑-xh….wav」）。
2. **词命中用用户原话**，不用 LLM 改写出来的关键词——实测改写成「嘟 转场 提示音」反而搅浑。
   LLM 的产出只用来提取时长/声道过滤条件。
3. 语义模式用**原句**走 `/api/v1/search`，和软件界面看到的结果一致。

## 五、已知限制

- APE/CAF 这类 Chromium 解不了的格式，面板里放不了（会在提示里说明，需回 EchoMind 试听）
- 词命中的同等分数（同一组词）之间顺序是稳定的插入序，不是「更好的先」，因为分数确实相同
- 语义检索默认关闭；打开后单次 6~15 秒，且会把事件循环占住（超时不保证及时中断）
- 面板只读：不改标签、不写描述（将来可以加）

## 三、那个唯一未解决的问题

### 现象

有一批配乐 MP3（`F:\CJ音效库整合包V1\音乐与乐器\完整配乐\` 下）音频向量一直 failed，界面显示 `audio_index_failed`（没有原因信息）。

### 已经确认的事实（都有实测）

```
文件          1. john powell - Victory Quest (121).mp3, 2.6 MB
ID3 标签      170,928 字节（内嵌封面）
音频起点      第 170,938 字节，帧同步 FF FA D2 64（合法 MPEG-1 Layer III）
时长          79.8 秒（纯 Python 帧头解析）
```

| 实验 | 结果 |
|---|---|
| PyAV 解码原文件 | ❌ InvalidData |
| PyAV 解码「剥掉 ID3」后 | ❌ 仍 InvalidData |
| **miniaudio 解码「剥掉 ID3」后** | ✅ **成功 79.8 秒** |
| 主进程 decode（现在） | ✅ ok 79.75s / 7,656,178 采样 |
| 主进程 waveform（现在） | ✅ ok 2000 峰值 |
| **音频向量（批量路径）** | ❌ 仍 failed |

**结论：不是模型限制，不是窗口长度问题，是解码器 + 打包依赖问题。**

### 已经做过的修复

1. `_strip_id3_tail()`：解码失败时剥掉 ID3 重试
2. `_decode_with_miniaudio()`：PyAV 仍失败时用 miniaudio 兜底
3. **打包缺 `cffi`** 导致 miniaudio 一直静默失败 → 显式 `import cffi` 修复，`_cffi_backend.cp313-win_amd64.pyd` 已进 exe
4. `_waveform_with_miniaudio()`：兜底自算峰值 + 指纹

**效果**：波形和文本向量已经能成功生成（`waveform failed` 49 → 0）。
